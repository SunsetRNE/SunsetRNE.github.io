# Termux 从零开始（三）：组合指令与实用套路

> 前两篇学完了单条指令，本篇学**把指令组合起来**。这是从"会打命令"到"会用终端"的分水岭——本站其他教程里那种一长串命令，拆开看全是本篇的组合规则。

## 一、连接符：把多条命令连成一条

```sh
命令1 && 命令2    # 命令1 成功，才执行 命令2
命令1 || 命令2    # 命令1 失败，才执行 命令2（兜底用）
命令1 ; 命令2     # 不管命令1 成没成，都执行 命令2
```

人话理解：`&&` 是"成了就接着干"，`||` 是"不成再走另一条路"，`;` 是"顺序执行不关心结果"。

```sh
cd 项目文件夹 && ls          # 进目录，成功就顺便看看里面有什么
pkg update && pkg upgrade    # 更新源，成功就连着升级（万能开场仪式）
cd 不存在的目录 || echo "没这个目录"   # 进不去就提示一句
```

> 本站教程里最常出现的就是 `A && B && C`：前一步成功才走下一步，一步失败整条停住，不会带着错误继续跑。

## 二、管道 `|`：把前面命令的输出"喂"给后面

`|` 像一个水管，左边命令的输出流进右边命令当输入：

```sh
ls | grep 关键词      # 列文件，只留下名字含关键词的（找文件神器）
pkg list-installed | grep python   # 已装软件里哪些带 python
cat 大文件 | head -20  # 大文件只看前 20 行
```

> 遇到"输出太多"的场景，第一反应就是给它接个 `| head` 或 `| less`。

## 三、重定向：把输出存进文件

```sh
命令 > 文件       # 输出写入文件（覆盖旧内容）
命令 >> 文件      # 输出追加到文件末尾（不覆盖）
命令 2>&1 | tee 日志.txt   # 报错信息也一起存，边跑边在屏幕上看（进阶）
```

```sh
ls > 文件清单.txt          # 把目录列表存下来
echo "今天开始折腾 Termux" >> 笔记.txt   # 往笔记里追加一行
```

## 四、后台运行：不用傻等

下载大文件、跑长任务时不想干等？放后台：

```sh
命令 &          # 放后台跑，马上回到提示符，继续干别的
音量减 + Z      # 把当前正在跑的程序挂起（暂停）
jobs           # 查看后台任务列表
fg             # 把最近的后台任务拉回前台
```

```sh
wget https://example.com/bigfile.zip &   # 后台下载，该干嘛干嘛
```

## 五、少打字的秘诀：历史与补全

```sh
↑ / ↓ 键      # 翻历史命令（比 history 快）
Tab 键        # 自动补全命令/文件名（打几个字母按一下）
!!            # 再执行上一条命令（sudo 忘了加？直接 !! 重来）
!$            # 上一条命令的最后一个参数（进阶）
```

## 六、新手最常用的六个完整套路（直接抄）

```sh
# 1. 装软件标准姿势（万能开场）
pkg update && pkg upgrade && pkg install 软件名

# 2. 克隆项目并进入
git clone https://github.com/用户名/仓库名.git && cd 仓库名

# 3. 运行下载来的脚本
chmod +x 脚本.sh && ./脚本.sh

# 4. 找一个"不知道在哪"的文件
find ~ -name "文件名" 2>/dev/null

# 5. 看日志最后 50 行（排错神器）
tail -50 日志文件

# 6. 一键看磁盘和内存
df -h && free -h
```

> 套路 2 和 3 是本站很多教程的开头两行——现在你应该能看懂它们为什么长这样了。

## 七、能力边界：Termux 能做什么，不能做什么

学完三篇，你可以放心地说"我会用 Termux 了"。但有个边界必须知道：

**Termux 原生能做的**：git 操作、跑脚本、装 python/node、下载文件、ssh 连服务器、起小服务——本站大部分操作都在这层。

**Termux 原生做不到的**：完整的 Linux 发行版环境（比如编译 Android 内核需要的那套工具链）。想用完整 Linux 得再装一层 `proot-distro`：

```sh
pkg install proot-distro
proot-distro install debian
```

但说实话：**手机跑完整 Linux 又慢又烫又吃内存**，编译类操作（比如本站那篇 [Android 内核编译完整流程](./android-kernel-build-with-ksu)）建议还是老老实实用电脑。手机上的 Termux 适合"轻量折腾"，不是重型编译机。
